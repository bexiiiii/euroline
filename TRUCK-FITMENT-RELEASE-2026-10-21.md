# Автоматическое разделение аналогов по типу транспорта

## Исходная точка

По просьбе пользователя до новой реализации закоммичено всё текущее состояние проекта: `aeeb3b1`. Секреты `.env`, сборки, временные браузерные файлы и скриншоты исключены. Коммит локальный, push не выполнялся.

## Правила

- Основная выдача аналогов — «Грузовики и прицепы». Требуется прямое свидетельство в карточке именно этой детали: идентификатор связанного транспорта/оси и явно грузовой/прицепной тип в структурированных полях UMAPI.
- `LINK.CV` сам по себе не доказательство: коммерческий транспорт включает не только грузовики. Бренды деталей, названия товара, OE-соседи, тоннаж и конфигурация колёс не используются как доказательство.
- Проверяются `PLATFORM_TYPE` у CV, `AXLE_STYLE`, `AXLE_TYPE`, `AXLE_BODY` у осей. При недостающих полях допускается до трёх дополнительных чтений связанных `/CommercialVehicle/{id}` / `/Axle/{id}`. Неопределённые/конфликтующие типы остаются UNKNOWN.
- Наличие грузовой применяемости достаточно для включения, даже если та же деталь применяется на легковом автомобиле. Это не гарантия совместимости с конкретным VIN или комплектацией.
- Только известная негрузовая применяемость → NON_TARGET, исключается из API-списка аналогов. UNKNOWN/PENDING → отдельная кнопка «Неподтверждённые». Отсутствующие поля в старом payload трактуются как неподтверждённые.
- Основная выбранная деталь и предложения 1С не фильтруются этим правилом; фильтр применяется только к аналогам. Цены/остатки по-прежнему привязаны к конкретным бренду и артикулу.
- URL `segment=unconfirmed` открывает отдельный список; переключение сбрасывает пагинацию, сохраняет бренд/сортировку/фильтр фото. Новая деталь открывается в основном грузовом режиме.

## Фон и кэш

Два worker-потока, очередь 512, не более 2048 in-memory задач. Дедупликация задач по locale + бренд + артикул. Полные результаты в Redis `umapi-oe-v1:fitment-v1:*`, TTL 6 часов; живые jobs 10 минут. Сбои не сохраняются как успешная классификация и допускают повторную задачу через 30 секунд. Проверка идентичности обязательна для детали и дополнительных CV/Axle ответов. Общие OE не передают статус применяемости соседям.

Пока есть PENDING, API возвращает `analogsLoading=true`; витрина догружает данные без очистки списка. Если очередь заполнена или проверка не закончилась в срок клиентского опроса, неизвестные позиции не становятся грузовыми. Повторный поиск продолжает проверку.

## Ограничение покрытия

UMAPI не всегда заполняет тип транспорта даже для известных грузовых моделей. Поэтому основная выдача может быть небольшой или пустой; эти позиции честно доступны отдельно. Нельзя обещать автоматическое определение всех грузовых деталей при неполных данных. Для расширения подтверждённой выдачи нужен дополнительный достоверный источник классификации транспорта, а не whitelist артикулов/брендов или наследование через OE.
