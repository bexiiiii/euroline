# Автоматическое обнаружение замен через OE

Дата: 21.10.2026. Статус: автоматический OE-подбор реализован и выложен 21.10.2026, проверен через рабочий API и браузер в обе стороны. Ключи и схема БД не менялись. Ниже сохранены исследование и ограничения данных.

## Реализация и приёмка релиза

- `AutomaticAnalogService` получает идентичность, карточку и OE из UMAPI, ищет кандидатов по точной паре OE-производитель + номер, сверяет продуктовую группу и известные общие характеристики. Нет специальных правил/seed-связей для WABCO/AUGER. Кандидаты объединяются с прямыми кроссами по бренду и артикулу, без транзитивного замыкания.
- Подбор выполняется по запросу в фоне: два worker-потока, очередь 32, до 64 OE, 500 строк на OE, 600 кандидатов, бюджет 90 секунд. Ограниченный/ошибочный результат помечается неполным; это не отрицательный успешный кэш. Повторная задача после ошибки допускается через 30 секунд.
- Каталожные данные и законченные результаты хранятся в Redis `umapi-oe-v1:*` на 6 часов. Цены/остатки в этот кэш не входят. Старый кэш прямых кроссов не заменяет OE-результат. Подтверждены новые Redis result-ключи обеих деталей; массовый сброс кэша не выполнялся.
- API возвращает `analogsLoading`; витрина автоматически догружает результаты, сохраняя выбранные фильтры. `refresh=true` не создаёт повторные записи истории поиска. Старые ответы не заменяют более новый запрос.
- 24 обычных backend-теста и 7 frontend-тестов прошли. Отдельный opt-in live-тест на реальном UMAPI с независимым пустым кэшем для каждой стороны прошёл: 114 OE-кандидатов для WABCO, 74 для AUGER, обе связи найдены, partial=false.
- Production API: WABCO → AUGER 71932, 174 итоговые записи; AUGER → WABCO 4410329212, 158 записей. В обоих случаях `UMAPI_SHARED_OE`, `UNVERIFIED`, без предупреждений, догрузка завершилась. Среди подтверждённых общих OE — DAF 0082826. Итоговые количества включают прямые кроссы, поэтому отличаются от количества OE-кандидатов.
- Production браузер Playwright подтвердил обе стороны и подпись «Замена по общему OE». Скриншоты: `output/playwright/oe-wabco-to-auger.png`, `output/playwright/oe-auger-to-wabco.png`. WABCO имеет собственный остаток 1000; AUGER не получает его остаток, цена не подменяется нулём.
- Alatrade проверен в авторизованном браузере: обе стороны присутствуют в «Возможных заменах». Big7: прямая сторона содержит замаскированную AUGER-позицию; обратная проверка остановлена гостевым лимитом, она НЕ считается подтверждённой.
- Сборки backend и storefront успешны. Next.js 15.5.28, пользователь node, read-only rootfs и no-new-privileges сохранены. Полная проверка TypeScript всё ещё не проходит на старых несвязанных ошибках; сборка использует существующий ignoreBuildErrors.
- Резервные исходники: `/home/behruz/backups/oe-20261021/source-before.tar.gz`. Rollback-образы: `euroline-backend:before-oe-20261021`, `euroline-storefront:before-oe-20261021`. Релизные образы: `euroline-backend:oe-20261021` (04cc743119b3), `euroline-storefront:oe-20261021` (e720bcb27c9b).
- Сам OE-релиз не реализовал строгую грузовую фильтрацию. Следующее обновление описано в `TRUCK-FITMENT-RELEASE-2026-10-21.md`: подтверждённые грузовики/прицепы по умолчанию, неизвестные отдельно. Глобальный прогрев и гарантия взаимозаменяемости для конкретного автомобиля не реализованы. Отсутствующие данные о применяемости не наследуются от соседнего аналога.

## Результат проверки

Текущий поиск использует `/v2/cross/{locale}/Analogs/{article}/{brand}`. Прямые ответы этого метода не связывают WABCO 4410329212 и AUGER 71932. Раньше AUGER попадал в выдачу через другую марку с тем же номером, SAMPA; возвращать смешивание марок нельзя.

Это подтверждает автоматическое обнаружение **кандидатов на замену по общему OE**, а не безусловную взаимозаменяемость на любом автомобиле. Прямой кросс, общий OE и применяемость — разные виды доказательств.

## Предлагаемая схема без ручного ввода пар

1. Определить выбранную деталь строго по бренду и артикулу, получить её каталожный ART_ID. Автоматически разобранный бренд из названия старого товара 1С не считать надёжным при неоднозначности.
2. Получить карточку `/Article/{id}` с `OE_CODES`, `PRODUCTS`, `CRITERIAS`, `LINK`. Сохранить дату, источник и идентичность детали.
3. Для каждого OE строить ключ `(производитель оригинала, нормализованный номер)`. Сохранять ведущие нули; не объединять похожие бренды без подтверждённых алиасов. Номер 0082826 в код не зашивать: он извлекается из ответа API, как и все остальные.
4. Обращаться к поиску по OE, с выключенными ArticleNumber/TradeNumber/EAN/IAMNumber. Отбирать только строки, у которых `ARL_TYPE=OENumber` и совпадает именно пара OE-бренд + номер. Альтернатива — брендовый endpoint с последующей сверкой OE карточки кандидата.
5. Сверять категорию детали, известные ограничения и характеристики. Конфликт стороны установки, размеров или применяемости нельзя игнорировать. Отсутствующее значение — неизвестность, не подтверждение совпадения.
6. Хранить индекс «деталь ↔ OE» и доказательства, а не вручную составленные пары. Тогда обе стороны находят друг друга через один и тот же OE. Это не означает разворот всех направленных замен или транзитивное объединение всех аналогов.
7. Объединять прямые кроссы и OE-кандидатов без дублей по бренд+артикул. Отдельно маркировать основания: `DIRECT_CROSS`, `SHARED_OE`; применяемость хранить отдельным статусом.
8. Цены, остатки и склады брать из 1С исключительно для конкретной совпавшей детали. Не копировать остаток WABCO на AUGER, даже если они являются заменами.

## Грузовой каталог

- Использовать связи с конкретными моделями/осями и их классификацию; бренд сам по себе не является признаком грузовой детали.
- `CV` означает коммерческий транспорт и может включать автобусы, поэтому одного наличия CV недостаточно для строгого режима «только грузовики».
- Для WABCO в проверенном ответе есть, например, DAF FA 65 CF 180/210 и FAV 65 CF 180.
- Для AUGER 71932 API не вернул прямую применяемость. Не наследовать её от WABCO как подтверждённую. Показывать отдельно как OE-кандидата с пометкой «Проверьте применяемость»; строгий фильтр подтверждённых грузовых деталей должен его исключать до получения дополнительных данных.
- Это реальное ограничение данных. Чтобы одновременно показывать AUGER и гарантировать грузовую применяемость, нужен дополнительный подтверждённый источник применяемости, а не ослабление фильтра скрытым правилом.

## Производительность и надёжность

- Постоянный индекс OE/карточек с TTL и обновлением в фоне; прогрев товаров 1С и популярных запросов. Возможность длительного хранения проверить по условиям поставщика данных.
- Холодный запрос: ограниченный бюджет обращений, явный статус догрузки, продолжение в очереди. Не делать десятки последовательных обращений в каждом HTTP-запросе пользователя.
- Пагинация обязательна. Обнаружено расхождение `rows=55` и `data.length=49`; нельзя считать `rows` количеством уникальных товаров или завершать обход только по короткой странице. Нужны ограничение числа страниц, дедупликация, остановка при отсутствии прогресса и проверка фактической семантики offset до реализации.
- Таймауты/429/5xx: ограниченные повторы с задержкой, сохранение доступного кэша, отметка неполного результата. Не кэшировать сбой как «аналогов нет».
- Ограничить число OE и кандидатов на задачу, продолжать обход в фоне. Не строить рекурсивное замыкание «аналог аналогов».
- Регулярная сверка/истечение данных, чтобы исправленные или удалённые связи поставщика не оставались навечно.

## Приёмка реализации

1. На чистом кэше WABCO 4410329212 автоматически обнаруживает AUGER 71932 через полученный из API OE; без seed SQL и специальных условий для этих артикулов.
2. Обратный поиск AUGER 71932 находит WABCO 4410329212 тем же механизмом.
3. У обеих записей виден источник общего OE; они не помечаются как гарантированно совместимые с любым автомобилем.
4. Другой бренд с таким же номером не получает чужие остатки/цены.
5. Одинаковый OE-номер у другого производителя и другая категория не объединяются автоматически.
6. Неизвестная применяемость остаётся неизвестной; проверен строгий грузовой фильтр и отдельный список OE-кандидатов.
7. Проверены пагинация, отсутствие дублей, холодный/тёплый кэш, удалённая связь, timeout и 429.
